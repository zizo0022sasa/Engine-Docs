# 🔄 بروتوكول الاستئناف الإلزامي والتعافي من انقطاع الجلسة (`RESUME_PROTOCOL.md`)

> **الإصدار:** `1.0`  
> **نقطة الدخول الإلزامية عند أي جلسة جديدة أو بعد كتابة كلمة «تابع»:** ملف [`PROGRESS.md`](../PROGRESS.md) في جذر المستودع.

---

## 1. معنى كلمة «تابع» (Deterministic Continuation Rule)

عندما يرسل المالك كلمة **«تابع»** (أو عند استئناف العمل بعد انقطاع الاتصال أو انتهاء مهلة الجلسة):
1. **يُحظر البدء من الصفر** أو إعادة كتابة ملفات أو وثائق أو اختبارات مكتملة ومثبتة في Git.
2. **لا يُعتبر انقطاع الاتصال دليلاً على فشل العملية السابقة ولا دليلاً على نجاحها**؛ الحكم الوحيد هو الفحص الفعلي لحالة المستودع، سجل الالتزامات، ونتائج الاختبارات.
3. يُستأنف العمل حصراً من **أول خطوة غير مكتملة ومصرح بها** في `PROGRESS.md` و`TASKS.md`.

---

## 2. خطوات الفحص الإلزامية عند الاستئناف (The 7-Step Resume Checklist)

يجب تنفيذ الأوامر والفحوص السبع التالية بالترتيب قبل تعديل أي ملف:

### الخطوة 1: استعادة الوصول وفحص حالة Git المحلية والبعيدة
```bash
cd /home/user/Engine-Docs   # أو استنساخ المستودع إذا كانت بيئة الساندبوكس قد أُعيد تهيئتها
git fetch origin
git status
git log --oneline -n 8
git diff --stat HEAD origin/main
```
* **قاعدة Recovery Candidates:** إذا وُجدت ملفات معدلة غير ملتزمة (`uncommitted files`) بعد انقطاع مفاجئ، **لا تحذفها بـ `git reset --hard` عمياء**؛ افحص محتواها بـ `git diff`، وصنّفها: هل هي تكملة صالحة للمهمة الجارية أم بقايا تالفة؟

### الخطوة 2: قراءة بوصلة التقدم والمهام
* اقرأ `PROGRESS.md` بالكامل لمعرفة: المرحلة الحالية، آخر التزام محقق، المهمة المفتوحة (`CURRENT_TASK`)، القرارات المعلقة، والخطوة التالية المصرح بها.
* طابق حالة `PROGRESS.md` مع `git log` الفعلي ومع `TASKS.md`. إذا كان هناك التزام كود نجح رفعه قبل تحديث `PROGRESS.md`، حدّث `PROGRESS.md` أولاً بعد التحقق من اختباراته.

### الخطوة 3: فحص الأمان والأسرار السريع
```bash
python3 -m osrs_ee.security.secret_scan .
```
* يجب أن تكون النتيجة `[SECRET_SCAN_OK]` قبل أي عمل أو التزام جديد. لا تحفظ أي توكن GitHub في ملفات المستودع؛ استخدم `~/.git-credentials` بصلاحية `0600` خارج شجرة المشروع فقط.

### الخطوة 4: التحقق من سلامة الاختبارات القائمة (عند الحاجة الهندسية)
* إذا كانت شجرة العمل نظيفة وآخر التزام في `PROGRESS.md` موثق النجاح ولم تتغير بيئة التشغيل، لا تُعد تشغيل كل شيء بلا مبرر؛ أما إذا وُجدت تغييرات معلقة أو أُعيد تهيئة بيئة الساندبوكس، فشغّل حزمة الاختبارات السريعة للتأكد من سلامة الأساس:
```bash
PYTHONPATH=. pytest
```

### الخطوة 5: معالجة العمليات ذات الأثر غير المعروف (`UNKNOWN` Reconciliation)
* إذا انقطع الاتصال أثناء عملية خارجية (مثل رفع Git أو عملية عميل مستقبلاً):
  1. افحص الأثر الفعلي أولاً (`git ls-remote origin main` للرفع، أو قراءة `CommandJournal` وحالة اللعبة للعميل).
  2. إذا لم تتوفر الأدلة اللازمة لحسم ما حدث، وثّق المشكلة في `PROGRESS.md` تحت قسم `العوائق الحالية` وتوقف عند الحد الآمن دون تخمين.

### الخطوة 6: تنفيذ وحدة عمل ذرية واحدة (`Single Atomic Work Unit`)
لكل مهمة من `TASKS.md`:
1. راجع متطلباتها وعقدها في `docs/` ومعايير قبولها في `docs/ACCEPTANCE_TESTS.md`.
2. نفّذ الكود ضمن النطاق المحدد فقط.
3. أضف/حدّث الاختبارات في `tests/` وشغّل `PYTHONPATH=. pytest` وسجل العدد الفعلي للاختبارات الناجحة.
4. شغّل `python3 -m osrs_ee.security.secret_scan .`.

### الخطوة 7: التحديث الذري والتوثيق والرفع الفوري
1. حدّث حالة المهمة في `TASKS.md` وسجل التقدم في `PROGRESS.md`.
2. أنشئ التزام Git واضح الرسالة يربط المعرف (`feat(state): PR-03 implement transactional SQLite store and lease fencing [T04,T07,T08,T09]`).
3. ادفع فوراً إلى `origin/main` عبر `git push origin main` (يُحظر `git push --force`) وتأكد من تطابق `HEAD` مع `origin/main`.
