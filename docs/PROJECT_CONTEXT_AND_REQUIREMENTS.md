### ما لم يتم التحقق منه ميدانياً حتى هذه اللحظة (`UNVERIFIED Boundaries`)
التزاماً بالصدق الهندسي الصارم، لم يتم في بيئة التأسيس الحالية:
1. تشغيل عميل لعبة OSRS حي أو الاتصال بسيرفرات شركة Jagex أو تجريب حسابات فعلية.
2. تجميع مشروع `Microbot` الكامل عبر Gradle ضد لعبة حية أو قياس الـ `RSS` الفعلي لـ 10 نوافذ على جهاز الهدف (Windows أو Linux VPS).
3. اختبار مزود بروكسي سكني مدفوع حي أو بوابة `chat_engen` بمفتاح مزود خارجي حي.
> جميع المكونات التي تعتمد على هذه العناصر تظل موسومة بـ `SPECIFIED` أو `HERMETIC_TESTED` فقط، ولا تُوسم `LIVE_VERIFIED` إلا بعد تنفيذ اختبارات البيئة المستهدفة (`PR-05` وما بعدها).

## 2. الأهداف والنطاق المرحلي: نواة `MVP` مقابل التوسع (`Post-MVP`)

الهدف الجوهري للمشروع هو بناء **منظومة إدارة وتشغيل موثوقة، معزولة، قابلة للاستئناف الآمن بعد الأعطال، ومحصنة الأدلة (`Reliability, Isolation & Evidence Engine`)** لتشغيل مهام لعبة OSRS وتقليل التدخل اليدوي، مع الإقرار الصريح بأن **جودة الهندسة تقلل أخطاء التشغيل والارتباط الشبكي/السلوكي لكنها لا تمثل ضماناً مطلقاً ضد الحظر (`No 100% Anti-Ban Guarantee`)**، وأن مخاطر شروط خدمة اللعبة تقع ضمن مسؤولية قرار المالك التجاري.

### أ. نطاق النواة الأساسية (`MVP Scope — PR-00 .. PR-06`)
1. **الأمان وحماية الأسرار (`PR-00`):** صفر أسرار في الكود أو السجلات أو التليجرام؛ إشارات مرجعية فقط (`credential_ref`, `proxy_ref`, `adapter_token_ref`)؛ فحص آلي للأسرار وصلاحيات الملفات.
2. **العقود والحالة الذرية (`PR-02`, `PR-03`):** مخططات صارمة (`JSON Schemas` + نماذج بايثون محققة)، ومخزن حالة محلي ذو كاتب منطقي واحد (`SQLite WAL` بمعاملات ACID + تصدير لقطة `state_snapshot.json` للقراءة البشرية)، وإيجارات حصرية متزايدة الجيل (`Lease + session_epoch`)، وسجل نوايا أوامر قبل الإرسال (`Write-Ahead Command Journal`)، ومنع تكرار الأحداث (`Event Deduplication`).
3. **التشغيل الأحادي المعزول والمحاكاة (`PR-04`):** مشرف جلسة واحدة (`concurrency = 1`)، بوابة أوامر وحيدة (`GameAdapterGate`)، عامل مهمة يلتزم بدورة `(اقرأ ◄ تحقق من الشرط المسبق ◄ وثق النية ◄ نفذ ◄ تحقق من الأثر البعدي)`، تمييز صريح لحالة `UNKNOWN`، هرمية إيقاف بثلاث مستويات (`pause / drain / abort`) بمهل حتمية، واختبار شامل ضد محول لعبة محاكي بحقن الأعطال (`FakeGameAdapter`).
4. **الربط القرائي ثم التجريبي المراقب على عميل واحد (`PR-05`, `PR-06`):** تهيئة Sandbox معزول بـ `Pre-Launch Profile Seeding`، نفق SOCKS5 محلي `Fail-Closed`، قراءة حالة موثقة الأنواع (`Varp 281` لا `Varbit 281`، والبنك المغلق = `UNKNOWN`)، ثم تشغيل مهمة واحدة مراقبة (`Stronghold` أو مهمة جمع أساسية) بموافقة المالك.

### ب. قدرات مؤجلة لما بعد إثبات النواة (`Deferred Post-MVP — PR-07 .. PR-10`)
* **بوت التليجرام التفاعلي (`PR-07`):** بعد إتمام RBAC، ربط الموافقات بالجلسة والخطة لمرة واحدة، وتقييد طابور الرسائل (`Bounded Outbox`).
* **المستشار الذكي `AI Advisory` (`PR-08`):** استشاري اقتراحات فقط (`Proposal Schema`) بدون سلطة تنفيذ مباشرة في MVP.
* **تعدد النوافذ والتحديثات المعزولة (`PR-09`):** بعد قياس `RSS` الفعلي على جهاز الهدف وبناء بوابة `Staging + Canary`.
* **تسييل الفائض بالبورصة والجدولة الاقتصادية (`PR-10`):** معطل تماماً في MVP لحين اكتمال دفتر أوامر الـ GE (`GE Order Ledger`) وحجز مدخلات الوصفات (`Active Recipe Input Lock`).
* **تحوير الكود المصدري (`AST Variable Mutator`) واكتشاف السكربتات التلقائي غير المراجع:** **ملغى/خارج النطاق التنفيذي** لثبوت عدم جدوى تغيير أسماء المتغيرات المحلية بعد ترجمة `javac` وخطورته على سلامة الحزم (`ADR-006`).
