## 🔒 1. ميثاق الأمان وحماية الأسرار (Security & Privacy Hygiene - P0)
* **حظر نشر التوكنات والمفاتيح وكلمات المرور:** يُمنع منعاً باتاً وضع توكنات Telegram أو مفاتيح الـ AI أو كلمات مرور الحسابات أو روابط البروكسي المحتوية على بيانات اعتماد داخل الكود أو التوثيق أو الـ Git أو رسائل التليجرام أو مطالبات الذكاء الاصطناعي.
* **المراجع بدلاً من الأسرار (`Reference-Only State`):** يحتفظ مخزن الحالة بمراجع فقط (`credential_ref`, `proxy_ref`, `adapter_token_ref`)، بينما تُقرأ الأسرار وقت الإقلاع فقط من مخزن محلي محمي بصلاحية `0600` ومستبعد بـ `.gitignore`.
* **تعطيل التليمتري الخارجي (`ADR-004`):** يُطلق كل عميل `Microbot` إجبارياً برايات `--disable-telemetry` و`-Dmicrobot.disableTelemetry=true`.
* **تنقيح التقارير والصور (`Redactor`):** تمر كافة السجلات والاستثناءات والتنبيهات عبر محرك `osrs_ee.security.Redactor` لاستبدال الهويات بمعرفات مستعارة (`acc_01`) وحجب أي سر مسجل.

## ⚖️ 2. توحيد الرؤية الهندسية بعد دمج تقارير التدقيق الثلاثة

| المحور المعماري | القاعدة المعيارية المعتمدة (`v2.1`) |
|---|---|
| **نطاق النواة (`MVP`)** | إثبات سلوت واحد مستقر (`concurrency = 1`) بعقود محققة ومخزن حالة ذري ومحول محاكاة بحقن الأعطال (`FakeGameAdapter`) قبل أي توسع متعدد النوافذ (`PR-00 .. PR-06`). |
| **مخزن الحالة الذري (`ADR-003`)** | قاعدة `SQLite (WAL)` ككاتب منطقي وحيد للحقيقة والإيجارات وسجل الأوامر ومنع تكرار الأحداث، مع تصدير تلقائي للقطة منقحة `state_snapshot.json` للقراءة البشرية السريعة دون التعرض لـ `WinError 5`. |
| **عزل الجلسة والعميل (`ADR-004`)** | عملية JVM معزولة جديدة لكل جلسة (لا يُعاد استخدام JVM واحدة بين حسابين أبداً)، مع تطعيم البروفايل والكاش مسبقاً وتفعيل `hwid-agent` وبوابة أفعال وحيدة (`GameAdapterGate`). |
| **قراءة الحالة واللعبة (`ADR-007`)** | قراءة مهيكلة تفصل `Varp` عن `Varbit` (`Tutorial Island = Varp 281`)، وتُرجع `UNKNOWN` (`null`) عند تعذر القراءة أو إغلاق البنك، وتلتزم بشرط فتح تداول F2P الحقيقي (`10 QP + 100 Total Level + 20h Playtime`). |
| **تحديثات العميل والـ Hub (`ADR-006`)** | لا سحب `git pull` في وقت التشغيل؛ التحديث يمر ببوابة محكومة: `(DETECTED ◄ STAGED ◄ BUILT ◄ CONTRACT_TESTED ◄ APPROVED ◄ CANARY ◄ ACTIVE)`، مع اعتماد سجل وصفات `TaskRecipe` بدلاً من `@ScriptDescriptor` أو `AST Mutator`. |
| **دور الذكاء الاصطناعي (`ADR-002`)** | مستشار اقتراحات فقط (`Proposal Schema`) في النواة الأساسية بدون توكن وصول للمحول، وحظر مطلق لإحداثيات البكسل `Click(x,y)` أو تأكيد التحذيرات المجهولة. |
| **الصدق الهندسي (`ADR-001`)** | الهندسة الجيدة تقلل أخطاء التشغيل والارتباط الشبكي والسلوكي لكنها **لا تمنح ضماناً مطلقاً (100%) ضد الحظر**؛ ويُفصل دائماً بين ما هو `SPECIFIED` وما هو `HERMETIC_TESTED` أو `LIVE_VERIFIED`. |

## 📋 4. القواعد الهندسية الحاكمة للمنظومة

1. **ملكية الحالة والأوامر (`Single-Writer & Single-Gate`):** لا يكتب في الحالة سوى `StateStore` بمعاملات ذرية، ولا يرسل أوامر للعبة سوى `GameAdapterGate` بعد التحقق من سريان عقد الإيجار (`lease_id`) وجيل الجلسة (`session_epoch`).
2. **سجل نوايا الأوامر قبل الإرسال (`Write-Ahead Command Journal`):** كل أمر مؤثر يُسجل `PREPARED` ثم `DISPATCHING` قبل خروجه للشبكة؛ وإذا انقطع الرد يُوسم `UNKNOWN` ويُحظر تكراره التلقائي قبل مصالحة الحالة الفعلية.
3. **البصمة السلوكية وتنويع النوافذ (`Persona Seed & Resolution Jitter`):** يُشتق لكل حساب من بذرته الثابتة (`account_persona_seed`) مقاس نافذة ثابت ضمن نطاق آمن (مثل `784x592`..`828x618`) وتوزيع زمن استجابة ملتوٍ لليمين (`Bounded Log-Normal`) مع كتم الأصوات وتجريد الإضافات الرسومية الثقيلة.
4. **فصل سقوف الأمان عن النطاقات التكيفية (`ADR-008`):** تُحفظ كافة المدد التكيفية كنطاقات `[min, max]` مفحوصة الصحة (`min <= max`) داخل سقوف أمان قصوى غير قابلة للتجاوز، وتُجمد للجلسة في لقطة مختومة (`config_hash`) باستخدام ساعات `monotonic` وانتظار قابل للإلغاء الفوري عند `abort`.
5. **العزل الشبكي الصارم (`1 Active Account = 1 Dedicated IP`):** يتصل العميل حصراً بجسر `SOCKS5` محلي خاص بالسلوت يطبق `socks5h` وسياسة `Fail-Closed`، ويُربط النطاق الجغرافي بمصفوفة العوالم الإقليمية الأقرب كموناً (`EG -> EU DE/UK`).
6. **الساعة البيولوجية الإقليمية (`Circadian Sleep Block`):** يلتزم كل حساب بنافذة نوم ليلي متصل (`7.5–10 ساعات`) متوافقة مع المنطقة الزمنية لنطاقه الجغرافي، ولا يُصفر عداد الراحة عند انهيار العميل.
7. **الحصانة الافتراضية وتأجيل التسييل (`Default-Deny Immunity`):** البيع التلقائي في الـ GE معطل في MVP (`ADR-006`)؛ وعند تفعيله في `PR-10` لا يبيع إلا عناصر `sellable_yields` غير المحجوزة في `Active Recipe Input Lock` عبر دفتر أوامر `GE Order Ledger`.
8. **الحجر الصحي بعد الموت والتعافي المحقق (`Post-Death Quarantine & Recovery`):** رصد الموت ينقل الحساب فوراً إلى `BLOCKED (DEATH_QUARANTINE)` لمنع حلقات الموت، وأي جلسة تنهار تنتقل إلى `RECOVERY_REQUIRED` (وليس `READY`) حتى تتم المصالحة الفعلية.
